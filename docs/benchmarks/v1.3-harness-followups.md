# v1.3 harness follow-ups (parked until the next study)

Findings from the 2026-08-23 review pass over PR #4. Every item below touches
code covered by the execution-harness fingerprint
(`eng/benchmark-presets.ps1` + `eng/benchmark/BenchmarkHarness.psm1`) or needs
live runs to verify. None of them affected the published v1.3 study: all 126
measured cells were non-resumed (`resumed_any` false), the study is clean, and
changing fingerprinted files before the merge would break the property that
HEAD reproduces the published evidence. Fix these together at the start of the
next study; by the harness's own rule, a harness change requires clean evidence.

1. **Resume-time accumulator is dead code** (`eng/benchmark-presets.ps1`,
   `Complete-KeeFetchRun` / `Invoke-ResumeCell`; see also
   `BenchmarkHarness.psm1`). `active_elapsed_ms` is written only at cell
   completion, so an interrupted cell can never carry a prior value and a
   resumed cold cell records only its resumed tail — systematically shrinking
   `active_batch_cold_ms`, which is the bulk-fast winner key. Latent in v1.3
   (zero resumed cells). Fix by threading prior active time through the
   incomplete-run state that resume already restores.
2. **Warm-block quarantine runs before the `schedule.json` identity check**
   (`eng/benchmark-presets.ps1`): a schedule mismatch aborts only after run
   directories have already been moved out of the evidence root. Reorder so
   identity is verified before any mutation.
3. **`harness_environment` uniformity is recorded but never enforced**
   (`eng/benchmark/select-profiles.ps1`): resumed-across-machines evidence
   passes every fingerprint gate. Enforce uniformity in the selector.
4. **Resume and quarantine-rebuild paths have no automated coverage**: the
   offline suite never exercises the runner's orchestration, and both live
   smokes are cold-only with `repetitions: 1`. Add a resume-path self-test
   when item 1 is fixed.
