### What changed in this session

1. **Authoritative Execution Policy (`FetchExecutionPolicy`)** (Phases 1–3):
   - Introduced immutable `FetchExecutionPolicy` containing ordered provider IDs, primary/fallback/cumulative timeouts, synthetic fallback flag, and `StopAfterStrongResolved` flag.
   - Deterministic SHA-256 policy fingerprint computed from canonical representation; both managed profiles and benchmark candidates resolve through the same code path.
   - `FaviconDownloader` resolves policy once and enforces hard wall-clock deadlines bounded by `min(provider budget, remaining cumulative budget)`. Retries never exceed the provider's budget.
   - `IconProviderBase` rethrows transport exceptions to keep provider errors distinguishable from empty results.
   - Unit tests added: `ExecutionPolicyTests.cs` and `ProviderDeadlineTests.cs` (19 new tests, suite now 139/139).

2. **Benchmark Execution & Matrix Provenance** (Phases 4–6, 10–11):
   - `profile-candidates-v13.json` updated with explicit `stopAfterStrongResolved` per candidate (fast/balanced = true, thorough = false).
   - Matrix cell identity: `candidate | cache_mode | repetition` with explicit repetition count and policy fingerprints in `run.json`.
   - Experiment-level resume and deterministic schedule with recorded seed.
   - Cold runs clear cache before each run; warm blocks perform clear-once + unmeasured warm-up over corpus, followed by measured warm repetitions without clearing.
   - `select-profiles.ps1` enforces exact expected matrix, matching fingerprints, and fail-closed provenance.

3. **Human Review Sampling & Ambiguity Sensitivity** (Phases 7–9):
   - Review queue identity is exact `(fixture_id, artifact_hash)`.
   - Must-review units: all synthetic, placeholder-suspected, blank-suspected, and profile-differing results. Remaining successes sampled uniformly within category|profile strata using deterministic SHA-256 ranking.
   - Statistical aggregation uses design weights (`population / sample`) and Wilson 95% confidence intervals; unreviewed successes are never counted as correct.
   - Ambiguity sensitivity check re-evaluates all 4 winner rules (`bulk-fast`, `everyday`, `privacy`, `max-coverage`) under conservative (ambiguity = failure) and optimistic (ambiguity = usable) assumptions; selection fails closed if ambiguity can reverse any decision.

4. **Task 6 Exporter Determinism & Publication Gate** (Phases 12–13):
