## Migration, rollout and recovery

Configuration migration maps legacy Fast → Fast, Balanced → Balanced, Thorough → Precise, and Custom/unknown → Custom. No database-format migration is introduced. Custom provider/order/timeout/synthetic/certificate settings and repeat-launch idempotency need visible verification.

Order: finish census/selection → freeze catalog/version → integrate/review and pass final-source gates → package and validate exact artifacts plus host/media → finalize notes/hashes → obtain merge/publication decisions → verify tag CI, GitHub Pages, downloaded hashes and a fresh downloaded-PLGX load. These last publication checks are rollout work, not completed pre-release evidence.

Back up configuration and the database with KeePass closed. On load failure, lost settings or incorrect icon changes, close KeePass and restore the saved plugin and affected configuration/database backups. Plugin rollback alone cannot undo downloaded icons. Recovery remains unverified on the final artifact.

Maintainer handoff should include the exact source/bytes and this gate status before publication. User-facing release notes should explain migration, provider disclosure, installation and recovery when the release is published. No external announcements were sent.
