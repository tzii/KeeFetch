## 7. Legacy configuration migration

Close the disposable KeePass before editing its `KeePass.config.xml`. Keep a
backup of that file. Use a separate copy for each case. Remove `KeeFetch.*`
items from that copy first so an existing profile ID does not bypass migration.

Ready-made synthetic configurations are in
`docs/validation/fixtures/v1.3-legacy-configs/`. With the test host closed, copy
one into its portable directory as `KeePass.config.xml`. These files affect only
the disposable host and avoid editing a real v1.2 configuration.

The Custom fixture expects: Direct Site then Yandex then Google in the order
list; Yandex disabled, Google enabled; timeout 13 seconds; synthetic fallbacks
off; third-party fallbacks on; private/internal certificate-chain override on.
Inspect those settings before and after Save/restart. The checked certificate
option is intentional fixture data for this migration check.

If creating your own case instead, use this format:
Inside `<Configuration><Custom>`, add the legacy preset item below (create
`<Custom>` if absent):

```xml
<Item><Key>KeeFetch.FetchPresetMode</Key><Value>Fast</Value></Item>
```

Run each case twice; open Settings, check the result, Save, close and reopen.
