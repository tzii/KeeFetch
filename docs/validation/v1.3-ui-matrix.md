## First-run/Settings persistence defect found and fixed (2026-08-28)

- Host experiment (e0051fd host, KeePass 2.60.0.0, `-cfg-local`): after opening the database and closing KeePass gracefully (WM_CLOSE, clean exit), `KeePass.config.xml` was byte-identical (SHA-256 `c4a3626b…b8440`, mtime unchanged at 2025-11-02). KeePass flushes its configuration file only when its own state changes; plugin `AceCustomConfig` writes are never flushed at exit.
- Consequence: the owner's confirmed Fast first-run choice (the 13:58 mixed run) and every Settings Save were silently lost between sessions. Checklist row 1's expectation (`KeeFetch.FetchProfileId` present in the config after exit) could not pass.
- Root cause: `ApplyFirstRunChoice` and `SettingsDraft.ApplyTo` wrote only to in-memory `AceCustomConfig`; no `AppConfigSerializer.Save` call existed anywhere in production code.
- Fix at `1ab737971c3f` (test-first): First Run confirmation and Settings Save now call `AppConfigSerializer.Save(Program.Config)` immediately after committing in memory; a persist failure is logged and does not abort the run. v1.2 migration-only sessions keep re-migrating idempotently by design. Three regressions: persist-after-commit (both write sites, verified in-memory state already committed when persistence runs), cancelled-choice no-persist, and validation-failure no-persist.
- Gates at `1ab737971c3f` with KeePass 2.60.0.0 (evidence `%TEMP%\KeeFetch-v13-ui-validation-20260828-153755`): Release solution, explicit C# 5 production build, and test build each passed with 0 warnings / 0 errors; MSTest 211/211 (0 failed, 0 skipped); benchmark harness self-tests, corpus validation, profile export `-Check`, and `git diff --check` passed.
