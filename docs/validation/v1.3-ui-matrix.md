### Ordered checklist

Execute in this order; each letter maps to the pending matrix rows.

1. **First install** (while the config is still pristine): trigger the first download (`Tools -> KeeFetch -> Download All Favicons`, confirm the 71-entry prompt with Yes). The First Run choice must appear before any network work. Cancel it: nothing is written and the run aborts (verify no `KeeFetch.*` keys appear in `KeePass.config.xml` after exit). Relaunch and this time confirm a profile choice; verify it persists (`KeeFetch.FetchProfileId` in the config, and Settings shows the same profile).
2. **Settings four-tab traversal at 100%**: `Tools -> KeeFetch -> Settings`, traverse Overview, Downloads, Providers, Advanced. Check Save/Cancel atomicity (Cancel discards edits), validation routing (enter an invalid timeout and confirm focus moves to the offending tab/control), resizing to minimum and larger.
3. **Keyboard-only**: Tab/Shift+Tab through every page once in logical order; Ctrl+Tab page switching; access-key mnemonics; Space toggles checkboxes/provider checks; arrows move selection; Enter invokes the default button; Escape cancels Settings and First Run without saving; Completion defaults to Close; after one retry the second summary offers no Retry.
4. **DPI 125%, 150%, 200%**: change Windows display scaling (restart KeePass when Windows requires it) and repeat the Settings/First Run/Progress/Completion traversal at each level: no overlap, clipping, or unreachable controls; long profile descriptions and long diagnostics paths remain readable.
5. **High Contrast**: enable a Windows High Contrast theme and repeat the traversal across all form states: text, focus, checked, error, and disabled states stay distinguishable without relying on color or icons alone.
6. **Cancellation under active work**: start a bulk download and cancel while network work is active. Verify Running -> Cancelling -> Cancelled wording and that cancelled entries are not counted as ordinary failures in the summary.
7. **Mixed result**: run a batch producing update, skipped, not-found, and recoverable failure outcomes (a database with existing icons plus a few unreachable domains). Verify totals equal processed entries and the diagnostics actions work.
8. **One retry**: from a mixed result, choose Retry Eligible. Verify only not-found/recoverable entries retry, successful icons are not reapplied or duplicated, and the second summary hides or disables Retry.
9. **Full success**: on a fresh database copy, verify counts, elapsed time, selected profile, diagnostics path, and Close behavior.
10. **Long diagnostics path**: nest the portable instance under a deeply nested temporary directory, run a batch, and verify the ellipsized display does not alter the copied path text and Open Diagnostics opens the exact file.
11. **v1.2 migrations** (config-edit cases, run each twice to confirm idempotency): for each legacy value, record the initial keys, the resulting `KeeFetch.FetchProfileId` (expected `bulk-fast`, `everyday`, `max-coverage` displayed as `Precise`, `custom`, `custom` respectively), preserved provider toggles/order/timeouts/synthetic/TLS for the Custom case, and that the second launch reads identically.
