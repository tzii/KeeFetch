01 / Availability-first selection

Not the first icon. The right icon.

KeeFetch collects candidates first, then ranks what survived. Strong site-backed icons stay ahead of placeholder-prone fallbacks instead of losing a race to whichever request happened to finish first.

01 / INPUT

Read the entry

Resolve URL placeholders, normalize schemes, map Android packages when needed.

02 / DISCOVER

Collect candidates

Site icons, Apple touch icons, manifests, resolvers, then fallbacks.

03 / VERIFY

Keep survivors

Reject broken responses and unusable candidates before selection.

04 / RANK

Trust beats luck

Site canonical → strong resolver → synthetic fallback.

05 / STORE

Dedupe + apply

SHA-256 keeps duplicate images out of the database.

02 / Built for messy real vaults

Fast when it matters. Fussy when it should be.

One entry or a whole database, KeeFetch is built to do the tedious icon maintenance without turning your password manager into a waiting room.

Selector engine

Quality has an order.

Provider candidates carry tier and confidence information so a weak synthetic answer cannot casually outrank a stronger site-backed result.

A / CONCURRENT

Bulk without the slog.

Parallel fetching keeps group and database-wide runs moving while KeePass stays responsive.

B / ANDROID

Android URLs, civilized.

Maps androidapp:// package names to web domains using built-in mappings plus Play Store fallback.

C / DEDUPE

No icon clone army.

SHA-256 deduplication avoids stuffing the same artwork into your database again and again.

03 / Privacy is a control surface

Know where your domains can go.

Third-party favicon resolvers can receive domain names from your entries when direct fetching is not enough. KeeFetch discloses that behavior on first run and gives you switches to narrow it down.

Visible defaults. Real controls.

Availability-first defaults keep resolver fallbacks enabled, but you decide whether third-party providers, synthetic fallbacks, or individual resolvers belong in your setup.

Tools → KeeFetch → Settings… No account required

Third-party providers

Disable external favicon services if you prefer direct-site fetching only.

Synthetic fallbacks

Keep generated or placeholder-style sources out of the candidate pool.

Specific resolvers

Turn individual services on or off instead of accepting one all-or-nothing bundle.

Existing custom icons

Skip entries that already have custom icons when doing maintenance passes.
